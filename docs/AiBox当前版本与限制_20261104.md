# AiBox 当前实测版本、修改与限制

## 版本身份

当前来源是非触摸 UI、BOOT 实体键、结束提示音 100 ms 预热的 2026-11-04 版本。

| 角色 | 当时端口 | 固件大小 | 原实测 nuttx.bin SHA256 |
|---|---|---:|---|
| TX | COM12 | 3345056 B | `ec611b27b6b35e26e830bbd6e709e12ef6d31fabb5b8d93d844422cf98821078` |
| RX | COM18 | 3345376 B | `4d4f059f43fc949f6aba80f05c8e5417c71f8144a3d7908ecec088eb349aa7fa` |

历史刷写后应用区回读与上述固件逐字节一致。此次整理改变构建路径，且配置做脱敏；新编译固件不承诺与历史 BIN 逐字节相同。历史二进制、ELF、配置、日志保留于忽略目录 `deliverables/firmware_aibox_20261104/`。本轮未再次连接串口、录音或烧录。

## 修改与量化记录

- 发送/接收简约 240×240 UI，按实体 BOOT 操作；当前默认 3 秒录音，录音过程中二次按键请求结束。
- 两声 880 Hz、150 ms 开始音，中间间隔 250 ms，开始提示保留 500 ms 稳定时间；结束音 660 Hz、180 ms，预热改为 100 ms。
- 原 500 ms 结束音预热的停止到提示函数返回约 778.985 ms；0 ms 时约 298.8 ms，但用户反馈低音轻/不完整；100 ms 时约 379.062 ms，用户反馈清楚、完整。不同轮次，仅作提示路径优化记录，不作为首音时延。
- 无串口读取器的当前真人麦克风轮次：34 包、坏包 0、丢包 0，解码 52224 采样，实际播放 48000 采样，播放墙钟 3020 ms，starvation=0、failed=0。只代表这一轮，不能扩展为长期丢包率或稳定性结论。

## 尚未解决与未覆盖

1. 用户曾反馈 BOOT 偶发不触发。忙时按键走停止请求，完成展示仍占用约 800 ms；部分轮次没有 GPIO 边沿，尚未证实全部现象由同一软件原因引起。
2. 固定输入并同时开启 TX 原始 PCM、RX 解码 PCM 导出的两轮，在进入结束音路径之前停止进度。失败记录保留于 `deliverables/aibox_current_validation/final_fixed_equivalence_04/`、`05/`；不得写成全量双路导出通过或新版音质等价已验证。
3. 用户“结束音之前最后 1 秒没录到”的反馈：先前配对波形显示既有采样尾部仍存在，但说话可能超出 3 秒窗口且结束音滞后。提示音延迟已缩短；仍需按实际录音窗口重新验证尾字，不把这个分析写成全部吞音问题已解决。
4. 本次没有重新做主观试听、真人首尾完整性、同频干扰和长时间稳定性试验；新目录构建结果与历史硬件结果分别记录。
5. 官方 manifest 基线移植尚待完成；参考 SDK 编译结果只覆盖参考 SDK。

AMR-NB 对比材料来自此前另一组固件与测试轮次，详见测评目录的版本/哈希记录。其平均音质、独立解码耗时不能直接套用到当前 UI 版本。禁止把历史 300 轮 BOX 测试当作当前 AiBox 的验收结果。
