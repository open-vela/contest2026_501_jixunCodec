# ESP32 当前版本与 AMR-NB 量化对照资料

日期：2026-11-04。两套编解码均实际在COM18这块ESP32-S3上运行；电脑只固定输入、收集数据与计算音频质量分数。

## 阅读顺序

1. [二者量化对比.md](二者量化对比.md)：对比总表、同输入窄带音质与结论边界。
2. [当前版本指标明细.md](当前版本指标明细.md)：新测纯解码3次，以及历史无线链路的成功、失败和诊断逐轮结果。
3. [AMR基线指标明细.md](AMR基线指标明细.md)：3段语音各3次、共9次的ESP32编解码实测。
4. [测评口径.md](测评口径.md)：计时、补尾、对齐、码率、内存与故障统计的定义。

## 可编辑数据

- `主要指标对比.csv`：中文主要指标，便于直接打开查看。
- `对比总表.csv`、`同输入音质对比.csv`：完整精度的主要性能与逐段质量对照。
- `当前版本逐轮指标.csv`、`AMR基线逐次指标.csv`、`音质逐次指标.csv`：所有实测明细。
- `量化指标汇总.json`、`测评口径.json`：结构化结果与定义。

## 输入、输出与复现

- `inputs/`：冻结的2秒固定音频、2秒真人音频、3秒固定音频，及544-token解码fixture的来源核对。
- `quality/`：两套实现经固定延迟对齐后的8kHz WAV，可试听比较。
- `evidence/COM18_decoder/`：当前AI三次纯解码及额外质量导出的串口记录。
- `evidence/COM18_history/`：此前COM12→COM18无线实测；失败数据同样保留。
- `baseline_amr/`：基线原始源码快照、固件、输入输出、9次计时与恢复资料。
- `scripts/`：测量、评分和报告生成脚本。当前完整报告可通过`python scripts/build_metrics_report.py`使用已保存的板端输出重新生成，不会再次运行PC编解码模型。

AMR基线来自用户指定的`${PROJECT_ROOT}/gl_prj\amr-nb`，使用其中随附的`amr_bench.bin`，未假称重新编译。基线实际启动日志确认ESP-IDF v5.5.5-dirty、240MHz、主任务CPU0、8MB PSRAM。当前AI为原接收固件f031b0fe…，使用原模型和通道数，未因测量修改算法。

## 设备与限制

COM12发送程序未改，COM18已从本次测试前现场读回的启动/分区/NVS/应用前缀恢复为当前AI接收程序，已确认自动接收`RX WAIT`，串口已释放。证据在`baseline_amr/recovery/final_state.json`和恢复日志。

本次AMR只测本地编解码，未实现AMR的LoRa或扬声器路径。AMR的解码计算时间不能直接当成无线首音时间。当前AI无线链路的丢包、发送卡住和PCM不一致仍是未解决项。两套运行框架、任务配置、采样率和码率差异均已披露；未测的CPU占用、同口径内存峰值和功耗不填造数值。

`SHA256SUMS.txt`用于文件完整性校验；`资料校验记录.json`保存本次结果数量、输入一致性、源目录未改和设备恢复核对。


整理说明：本目录仅收录公开报告与指标。原始日志、PCM、固件和分析依赖保留在仓库忽略目录 `deliverables/esp32_metrics_comparison_20261104_035832/`；文件内 `${PROJECT_ROOT}`、`${BUILD_HOME}` 表示原测评环境根目录。历史固件与本次 UI 固件须分别识别。
